# 初期データ規約

## 位置づけ

この文書はM0で作成した基礎方針である。M3以降、構造の正本は `schemas/*.schema.json`、責任分担は `standards/data-schema.md`、各領域の意味規則は該当する `standards/*.md` とする。この文書とM3成果物が食い違う場合はM3成果物を優先し、差異を無言で併存させない。

## 正本の形式

- 教材本文：UTF-8のMarkdown
- 語彙、例文、問題、出典記録等：UTF-8のJSON
- 技能依存関係、課程マップ：UTF-8のYAML
- 表示：HTML、CSS、Vanilla JavaScript
- 検査・静的生成：Python 3
- 文字列は保存前にUnicode NFCへ正規化する。
- レコードの `created_at`、`updated_at` と確認日時はタイムゾーンを含むISO 8601日時とする。日付だけを表す `updated_on` 等は `YYYY-MM-DD` とする。
- JSONのキーと機械可読IDは原則としてASCIIを使う。

## 分離原則

- Markdown本文を問題データの正本にしない。
- 問題JSONを画面レイアウトの正本にしない。
- 表示プログラムへ教材内容を直接固定しない。
- 配布用生成物は編集対象の正本とせず、生成元から再作成できるようにする。

## 識別子

- 単元、技能、語彙、例文、問題、出典には安定した一意IDを付ける。
- IDは表示名から独立させ、表示文言の修正で変更しない。
- ID形式は `schemas/common.schema.json` を正本とする。単元は `unit-`、語彙は `lex-`、例文は `ex-`、問題は `q-`、資料は `src-`、確認記録は `review-` を基本とし、技能IDは領域を先頭にしたドット区切りとする。
- 削除したIDを別の意味で再利用しない。

## 確認記録

`draft` は制作状態として表現する。次の三項目は独立した確認記録とし、単一の文字列へまとめない。

- `source_checked`
- `editorial_approved`
- `expert_reviewed`

各確認記録は、少なくとも次を表現できるようにする。

- 確認の有無
- 確認者
- 確認日
- 確認した版または内容
- 注記

Codexによる検査は `expert_reviewed` の根拠にしない。

## 出典と生成根拠

- 文法規則、例文、問題は、ゼロ個以上の出典IDと生成根拠を参照できるようにする。
- 出典記録には、書誌情報、確認可能な所在、利用条件、商用利用可否、改変可否、確認日を保持できるようにする。
- 原典からの引用、教材用の翻案、完全な教材用生成例を区別する。
- 確認できない資料を確認済みとして記録しない。

## 技能・語彙の追跡

- 教材項目は、必要な技能、新出技能、復習技能、使用語彙を参照できるようにする。
- 各語彙は見出し形、表示形、長母音つき形、品詞、初出単元、使用可能時点、時代・文体を保持できるようにする。
- 未習技能・未導入語彙を意図的に使う場合は、理由と学習者への扱いを明記する。

## 正書法と採点

- 内部正規形、教材上の表示形、許容入力形、採点時の比較形を分離する。
- 大小文字、空白、句読点、長母音、`i/j`、`u/v` の扱いは問題種別ごとの正規化プロファイルで指定する。
- 長母音の識別を問う問題では、長母音記号を採点対象にできなければならない。
- 自動採点問題は、正答、許容解、採点対象、正規化、別解析、解説を保持できるようにする。
- 自由作文と完全な羅文和訳は、初期版では自動的な一意採点の対象としない。

## 変更互換性

- 将来スキーマへバージョン番号を付ける。
- スキーマ変更は `logs/decisions.md` に記録する。
- 承認済みデータを変更する場合は、確認状態の再評価が必要か判断して記録する。
