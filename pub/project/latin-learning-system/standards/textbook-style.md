# 教科書本文・例文規約

## 1. 対象と文章

- 中学英語修了程度の日本語話者、特に成人独学者を中心とし、中学生にも読める平易な日本語を用いる。
- 「平易さ」は漢字率や一文の長さだけで自動判定しない。用語の定義、論理の飛躍、前提知識、例との対応を人間が確認する。
- 必要な文法用語は避けず、初出時に平易な定義と対象技能IDを示す。
- 日本語文法・英文法は補助線に限る。ラテン語の格・一致・支配・屈折を日本語助詞や英語語順へ還元しない。
- 簡単さのために不正確な規則を採らない。初級向けに範囲を限定するときは、適用範囲、保留する例外、再訪予定を明示する。

## 2. 説明ブロック

原則として一ブロックの中心概念は一つ、多くても密接な二つまでとする。M2の新出技能数は単元全体の予算であり、一段落へ同数を詰め込む許可ではない。

標準の流れは次とする。

1. 観察可能な目標
2. 平易な説明と用語定義
3. 短い例または形式表
4. 語形が文中で果たす働き
5. 誘導練習への接続
6. 適用範囲・よくある誤り・次の再訪

規則・構造理解と暗記事項を別見出しまたはラベルで示す。「覚える形」と「形を使って判断する方法」を混ぜない。詳細な日本語・英語比較、歴史言語学、例外、韻律、教会式発音は補足・発展欄へ分離する。

## 3. 表示要素

- 初級のラテン語・語彙表示には長母音記号を用いる。正規形、表示形、原典引用形を混同しない。
- ラテン語本文、語義、形態情報、統語機能、構造対応訳、自然訳を別フィールド・別ラベルで表示する。
- 表は列見出し・行見出しを持ち、色だけで分類しない。複雑な結合セルを避け、印刷時も意味が残る。
- 見出し階層を飛ばさず、注記には「注意」「予告」「未分析」「発展」等の文字ラベルを付ける。
- スクリーンリーダーで読み上げ可能なテキストを持たない図だけで文法関係を示さない。

## 4. 未習事項と予告

- 使用技能・語彙は単元の利用可能集合に含まれなければならない。
- 未習要素を意図的に示す場合、`exposure_state: preview` または `unanalyzed` とし、採点対象外、正式導入単元、学習者が今することを明記する。
- 予告を `introduced`、`review`、`assessed` として数えない。
- 未分析要素は、訳・意味を与えるだけか、形を固定して認識だけ求める。生成、完全解析、一般化を要求しない。

## 5. 2Cの述語形容詞

- 2Cでは「主語について述べる語」と認識する範囲に限定する。
- 第1・第2変化形容詞の体系、性・数・格の一致を既習扱いしない。
- 未習の語形生成、一致特徴の完全分析、曲用表の再現を要求しない。
- データでは `exposure_state: preview`、`counts_as_introduced: false`、`production_required: false` とする。
- 正式技能 `morph.adjective.declension12.basic` と `morph.agreement.gender-number-case` は4Cまで導入済みにしない。
- 2Cを省略しても4Cの強い依存関係は破綻しない。2Cは推奨的な橋渡しである。

## 6. よくある誤り

誤りを人格評価せず、観察可能な誤概念として書く。例：「最初の名詞を必ず主語とみなす」「語尾が同じなら一致しているとみなす」。誤り、なぜ起きるか、確認する既習技能、修正手順を分ける。未習事項を知らなければ理解できない警告を置かない。

## 7. 出典表示

本文中は資料IDとlocatorへ結びつけ、読者向け表示は短い書誌表記に変換できるようにする。引用、要約、翻案、独立生成を区別する。生成説明・生成例は古典作品からの引用でないと明示する。

## 8. 例文レコード

例文は `schemas/example.schema.json` に従い、少なくとも次を分離する。

- 例文ID、`canonical_form`、`display_form`
- token列と表示句読点。token境界は形態解析単位で、句読点は別レコードとする。
- tokenごとの表層形、lemma ID、形態特徴、統語機能、head、採用解析
- 文全体の使用技能、必要読解技能、使用語彙
- `introduced`、`review`、`preview`、`unanalyzed` の提示状態
- 未分析要素と、学習者に要求しない分析
- 構造対応訳、自然訳、語ごとの注釈
- 出典参照または生成根拠、時代、文体、レジスター、review履歴

一つの表層形に複数解析がある場合、`selected_analysis` と `alternative_analyses` を記録する。文脈で一意に決まらない解析を、自動採点の唯一の正解として使わない。

## 9. 生成例と引用例

- `origin_type: generated` は実在作品からの引用でない。
- `origin_type: quotation` は作品、箇所、版、電子化元、改変有無を記録する。
- 「古典ラテン語として妥当」は人間の文法・レジスター評価であり、「古典作品から引用した」と同義ではない。
- 生成例にも生成目的、使用可能技能・語彙、類推した規則、確認記録を持たせる。
