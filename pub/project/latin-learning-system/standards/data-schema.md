# データ規約の正本と責任範囲

## 1. 目的

この文書は、同じ規則を複数箇所へ矛盾して記録しないため、M3以降の正本、派生情報、検査責任を定める。構造上妥当であることと、教材として正しいことは別である。

## 2. 正本一覧

| 正本 | 責任範囲 | 正本ではないもの |
|---|---|---|
| `schemas/*.schema.json` | 型、必須項目、ID・日時形式、列挙値、条件分岐、局所的な構造制約 | ラテン語の正確性、説明の平易さ、参照先の実在、正答の意味的一意性 |
| `standards/*.md` | 教育的意味、制作手順、禁止事項、承認・失効、人間評価 | 機械的な型定義の細部 |
| `standards/normalization-profiles.json` | 正規化プロファイルIDと処理順序・各変換の機械可読な正本 | 正規化を使ってよい教育目的の説明 |
| `curriculum/latin-skill-map.yml` | 技能ID、領域、強い前提、推奨順、並行導入、初出 | 習熟段階、単元の負荷上限 |
| `curriculum/curriculum-map.yml` | 単元順、単元固有の前提・新出・復習、暫定上限、学習段階、復習配置 | 一般的な制作規則 |
| `lessons/*/unit-spec.yml` | 小単元の観察可能な目標、許可・禁止構造、人間確認事項 | 教材本文・問題の正本 |
| `sources/source-policy.md` | 出典確認、引用・要約・翻案、権利、`source-checked` 条件 | 個別資料の書誌値 |
| `sources/bibliography.json` | 個別資料ID、書誌、確認範囲、権利・利用条件 | 個々の教材記述が確認済みかという判断 |
| `logs/decisions.md` | 採用理由、却下案、影響、再検討条件 | 現在のデータ状態 |
| `logs/iteration-log.md` | 各反復で実行した変更・検査・結果 | 規則そのものの正本 |

## 3. 必要な重複と派生情報

- 単元仕様の技能一覧は `curriculum-map.yml` から `unit-spec.yml` へ編集用に重複する。正本は課程マップで、M4は両者の集合一致を検査する。
- `introduced_in` は技能マップに保存し、課程マップの `new_skills` からも導ける。M4は一対一一致を検査し、矛盾時は完了を拒否する。
- `enables` は保存せず、`requires` の逆向き索引として生成する。
- 正規化プロファイルの表は文書にも要約するが、処理順と真偽値の正本は `normalization-profiles.json` とする。文書とのID一致をM4で検査する。
- reviewの現在有効性は履歴から導出する。`current_approval: true` のような手書き派生値は保存しない。

## 4. 共通データモデル

教材本文メタデータ、例文、語彙、問題、単元レコードは、適用可能な範囲で次を持つ。

- `id`：安定したASCII ID。表示名変更で変えない。
- `schema_version`：データが従うスキーマ版。
- `content_version`：内容の意味的版。承認記録はこの値へ結びつく。
- `title`：人間向け表示名。
- `created_at`、`updated_at`：タイムゾーンを含むISO 8601日時。
- `source_refs`：単なる資料一覧ではなく、記述との対応箇所・確認範囲を持つ参照。
- `evidence`：資料要約、独立生成、設計判断、検査結果等の根拠種別。
- `skills`：必要・対象・復習・予告等、レコード種別に応じた技能参照。
- `vocabulary`：使用する語彙IDと扱い。
- `review`：制作状態と独立した確認履歴。
- `notes`：機械判定に使わない補足。

すべてのレコードに不適切な空配列やnullを強制しない。個別スキーマが必要項目を決める。

## 5. 出典参照と確認の分離

`source_refs` は少なくとも次を表現できる。

- `bibliography_id`
- `locator` 内の `page`、`section`、`paragraph`、`url_fragment`
- `claim_scope`：何を支える参照か
- `quotation_used`
- `verification_status`
- `verification_note`

資料IDが存在するだけでは `source-checked` ではない。該当箇所、対象版、記述との対応、利用形態、権利条件を確認し、別のreview履歴に合格記録が必要である。

## 6. `additionalProperties` 方針

- 教材レコード、レビュー、出典参照、正規化プロファイルは誤記を検出するため原則falseとする。
- M2のJSON互換YAMLは既存データを意味変更せず受け入れるため、説明用の可変オブジェクト部分だけtrueを許す。技能ノードや単元の主要フィールドはfalseとする。
- 将来拡張は、スキーマ版更新、明示的な `extensions` オブジェクト、または列挙値追加で行い、未知フィールドを無条件に黙認しない。

## 7. 検査責任の分類

### JSON Schemaで検査可能

型、必須項目、列挙値、ID・日時パターン、局所条件、品詞別必須項目、問題形式と自動採点可否、レビュー記録の形、M2データの基本構造。

### M4の検査プログラムで検査予定

外部ファイル参照の実在、技能・語彙の導入時系列、DAG循環、正規化後衝突、承認の最新版判定、正答集合と不正答集合の分離、単元上限、M2重複情報の一致。

### 人間確認が必要

ラテン語の正確性、説明の平易さ、訳の妥当性、例文の古典性・自然さ、問題の教育的価値、意味的一意性、負荷、出典解釈、権利上の最終判断。

## 8. M2互換性

M2の7ファイルはJSON互換YAMLのまま保持し、配列・技能依存・単元順を変更しない。M3のスキーマは現状を表現する。正式レビュー履歴をM2へ追加する移行はM4以降に別判断とし、M3では既存の三真偽値を `m2ReviewFlags` として保守的に検証する。
