# 正書法・正規化規約

## 1. 四つの形式

- `canonical_form`：内部で一つに定めるNFCの正規形。比較結果ではなく編集上の正本。
- `display_form`：教材・引用・辞書表示に使う形。長母音や引用元の綴りを保持できる。
- `accepted_input_forms`：問題ごとに明示された許容入力。無制限な表記揺れではない。
- `comparison_form`：採点時にプロファイルを適用して一時生成する値。正本として保存しない。

## 2. 機械可読な正本

プロファイルID、処理順、各変換の値は `normalization-profiles.json` が正本である。この文書は教育目的と禁止条件の正本である。M4は文書に列挙された5 IDとJSONのID一致を検査する。

## 3. 共通処理順

1. 入力を文字列として受け取る。
2. Unicode NFCへ正規化する。
3. プロファイルが許す場合だけ前後空白を除く。
4. プロファイルが許す場合だけ連続空白を一つへ畳む。
5. 大小文字を処理する。
6. 句読点・アポストロフィ類を、指定された集合だけ処理する。
7. 長母音記号を保持または除去する。
8. `i/j`、`u/v` を許可された方向へ畳む。
9. comparison formを生成し、正答・許容解・拒否解を同じ手順で比較する。

結合文字入力はNFC後に扱う。想定外の結合記号を無言で削除しない。ASCIIアポストロフィ、右単引用符、modifier apostropheを同一視するのは、その問題で句読点非採点が明示された場合だけとする。

## 4. プロファイル

- `meaning-default`：意味・構造を問う。大小、通常空白、採点対象外句読点、長母音、i/j、u/vを許容できる。
- `morphology-default`：語形の語尾を保存し、大小・空白・採点対象外句読点・長母音・i/j・u/vだけを処理する。異なる語尾や文字を一般的に削除・置換しない。
- `macron-sensitive`：長母音を保持し、長短を問う。長母音除去は禁止。
- `orthography-strict`：NFC以外を原則変更せず、指定綴り自体を問う。
- `structured-features`：文字列でなく格・数・性・人称等の列挙値を比較する。

## 5. 禁止条件

- 長母音問題に長母音除去プロファイルを指定しない。
- 語形問題で異なる語尾を同一視しない。
- i/j・u/vを問う問題では、それらを畳むプロファイルを使わない。
- 正規化後に正答集合と拒否集合、または異なる選択肢が衝突する問題は自動採点しない。
- 原文引用の綴りをcanonical formへ無言で書き換えない。

JSON SchemaはプロファイルIDと長母音問題の局所対応を検査できる。実際の変換と衝突計算はM4の検査プログラムが担う。
